# Case: rejected FAQ draft about AI features (<coursecode> CE-Quiz FAQ)

Session 2026-08-23. User asked for a forum FAQ post "How to use AI features in CE-Quiz?". First draft was rejected for three factual errors, each fixable by reading `public/ai/placement/courseassist/` source:

| Draft claim | Reality | Source evidence |
|---|---|---|
| "select the content you want AI help with (e.g. the question text)" | No selection — the whole main content region is sent | `amd/src/placement.js` `getTextContent()` → `document.querySelector('[role="main"]').innerText` |
| "click **Generate**" | No Generate button; clicking Explain/Summarise starts immediately | `placement.js` `registerEventListeners()` → `displayAction()` straight after policy check; `templates/loading.mustache` shows "Generating your response..." + Cancel |
| Link to `https://docs.moodle.org/en/AI` | No such page (user: "non-existent"; CDX shows no snapshots; only `en/AI_tools` + `en/AI_providers` have 2026 snapshots) | Wayback CDX probe |

Also dropped per user: the "Moodle 5.2" version reference (no clear student-facing version docs; the feature has no stable student doc anchor).

## Corrected flow (what the approved body should describe)

1. **AI features** button (sparkles icon) near top of the page → dropdown: **Explain** / **Summarise** (both present → dropdown, `templates/actions_dropdown.mustache`; string `aifeatures` = "AI features").
2. First use → policy block ("Accept and continue" / "Decline", `ai/templates/policyblock.mustache` + `lang/en/ai.php` `userpolicy` text).
3. Response card headed **AI explain** / **AI summary** (strings `aiexplain`/`aisummary`), watermark "Generated by AI" (string `contentwatermark` in core_ai), **Regenerate** + **Copy** buttons (`templates/response.mustache`).
4. Failure card: "Something went wrong" / "Try again later" + Try again button (`templates/error.mustache`).

## Verification technique for dead external links

From this pod, docs.moodle.org returns a Cloudflare challenge page for every fetch method tried (curl with browser UA, r.jina.ai, MediaWiki api.php); SPN is blocklisted. Reliable existence check: Wayback CDX index
`curl -s "http://web.archive.org/cdx/search/cdx?url=docs.moodle.org/<prefix>&limit=N&fl=original,timestamp&collapse=urlkey"`.
A URL with zero snapshots is a red flag; a URL with recent snapshots is probably live. Caveat: archived page copies of docs.moodle.org can themselves be Cloudflare challenge pages, so CDX confirms existence, not content. If content can't be read, flag the link and have the user click-test before publishing.
