# Moodle AI Course-Assist (Explain / Summarise)

Student-facing AI feature on <moodle-host> (Moodle 5.2.1): an **AI features** button (sparkles icon) on activity pages (e.g. quizzes) offering **Explain** and **Summarise** of the current page content. Plugin `aiplacement_courseassist` is enabled on this site; capabilities allow students by default.

## Before writing student-facing content about any UI feature

**Verify from source, never from general knowledge.** The user rejected a draft that invented a "Generate" button, misdescribed the input (selection vs whole page), and linked a non-existent docs page. Source of truth for AI features:

## Verified UI flow (Moodle 5.2.1 source)

1. On an activity page (CONTEXT_MODULE), the **AI features** button (sparkles icon, in the page header area at top of page) opens a dropdown with **Explain** and **Summarise** (two actions → dropdown; a single action → single button).
2. Clicking either starts generation **immediately** — there is **no "Generate" button**. Loading shows "Generating your response..." with a Cancel option.
3. **First use only:** an AI usage-policy block appears first — **Accept and continue** / **Decline**. Declining closes the drawer.
4. Input is **not a text selection**: `getTextContent()` sends the entire main content region of the page (`[role="main"]` innerText) — for a quiz, the current question content.
5. The response appears in a right-side AI drawer card headed **AI explain** or **AI summary** (sparkles icon), with a small "Generated by AI" watermark, and **Regenerate** + **Copy** buttons.
6. On failure: "Something went wrong / Try again later" with a **Try again** button.
7. **Regenerate** discards the previous response for that action and re-requests.

## Availability preflight (all must hold — `assist_ui.php`)

- Not during install; plugin installed + enabled (`mdl_config_plugins` `aiplacement_courseassist` `enabled=1`)
- Page layout not maintenance/print/redirect/embedded
- Page context is `CONTEXT_MODULE`
- `$PAGE->get_ai_visibility_hint()` is true (default true; quiz pages don't disable it; the restricted-module course route does)
- Capability `aiplacement/courseassist:explain_text` / `:summarise_text` (students allowed by default)
- `core_ai\manager` checks: action available, enabled for the placement, and enabled in the context

Provider-side "Something went wrong" (cURL/HTTP-blocking the AI provider) is a different class — see skill `moodle-curl-security-for-ai`.

## Student-content preferences (Dr. Chan)

- Do **not** name the Moodle version (e.g. "Moodle 5.2") in student-facing AI text — version-specific docs aren't useful to students.
- Descriptions must match the actual UI: whole-page content, immediate generation, **AI features** dropdown. Never say "select the text" or "click Generate".
- Always include the caveats: AI output may not be accurate — check against lecture materials; the feature is experimental, optional, and may not always work (slow/unavailable responses, retry available).

## Verifying docs.moodle.org links from this pod

docs.moodle.org sits behind a Cloudflare challenge against our egress IP: direct curl (any UA), r.jina.ai, and the MediaWiki `api.php` all return a "Moodle challenge" 403. Save-Page-Now is on the terminal blocklist.

Use the **Wayback CDX index** to check URL existence:

```bash
curl -s "http://web.archive.org/cdx/search/cdx?url=docs.moodle.org/en/AI*&limit=50&fl=original,timestamp&collapse=urlkey"
```

- Known-good (2026 snapshots confirmed): `docs.moodle.org/en/AI_tools`, `docs.moodle.org/en/AI_providers`.
- `docs.moodle.org/en/AI` (no suffix) has no snapshots — do not link.
- Caveat: archived copies of docs.moodle.org pages themselves served Cloudflare challenge pages, so CDX proves *the URL was captured*, not its content. When you must pick a link you cannot read, state that explicitly and ask the user to click-test before publishing.
